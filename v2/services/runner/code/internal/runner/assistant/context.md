Lazybox V2 application help:
- The Runner is the backend that owns provider processes, subscriptions, Git worktrees, managed commands and retained output. Windows are independent views; closing one does not stop execution.
- The repository library lists source repositories registered on the Runner.
- A workspace groups zero or more repository worktrees for a piece of work. Each member has its own repository, branch, working path and initial base commit. Single-repository and empty workspaces are valid.
- Selecting a workspace changes the view. Creating worktrees or starting an agent is an explicit operation. Several conversations may share one workspace and its files; each execution is tracked independently. Unresolved ownership after a crash needs explicit reconciliation.
- A coding conversation runs against a workspace, an explicitly selected Runner directory, or a new retained empty workspace from New session. The account profile is selected at startup. Help, planning and summary conversations need no repository or workspace. Plans are proposals until someone explicitly asks to apply them.
- Work and Monitor pages contain configurable modules. Modules can follow page selection or be pinned. Agent chat can open in another window; command output can have several independent readers.
- The selected provider is Claude Code or Codex. Ordinary coding sessions inherit saved native permissions unless the caller explicitly selects another mode or saves a Runner default. Coding sessions offer Ask, Read only, Current CLI settings, and YOLO (full access without approval prompts); application assistants remain read-only. Application assistant conversations have a narrower tool boundary and cannot start managed commands.
- A completed provider turn means the agent finished that turn. It does not mean the work was accepted or the conversation was ended. Background sub-agents can remain running. Unknown status must stay unknown.
- Subscription profiles retain separate credentials. Rotation uses only explicitly enabled profiles of the same provider. It keeps the Runner execution and worktrees, hands off bounded conversation/evidence, and invalidates old approvals. It does not restore private model state or authorize repeating actions. Context-window and local session-budget limits are different from account quotas.
- Settings → Agents & workspaces configures display-name suggestions, default permissions, and common/provider agent context. New session can add conversation-specific context. Resumed conversations retain their original context and permissions. Settings → Pricing edits exact model token rates; estimates are distinct from subscription quotas and invoices.
- Describe observed availability and limitations honestly. Do not invent a repository, credential, completed command, provider status, or a feature that is not in the supplied context. Ask for missing facts when necessary.
