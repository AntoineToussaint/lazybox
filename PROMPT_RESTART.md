# Restarting from an earlier prompt

**Implementation and release roadmap · 24 November 2026 · feature/arriere**

Suppose prompt three changed an API and prompt four updated its callers. You want to try a different API. Choose prompt three and edit it. The new agent should remember prompts one and two, see the files as they stood before prompt three, and have its own workspace. You should still be able to open the first attempt and compare the results. That is the default this branch implements for managed workspaces.

## Three ways to go back

| Surface | How you choose the point | Conversation and files |
| --- | --- | --- |
| Claude Code CLI | Press Esc twice with an empty input, or use `/rewind`. Choose a prompt and what to restore. | Claude offers conversation restore, code restore, or both when file snapshots are available. Its checkpoints follow files touched by Claude’s editing tools. Shell-only changes and many subagent edits fall outside that coverage. Claude also offers `/branch` for a separate conversation. [Claude Code checkpointing](https://code.claude.com/docs/en/checkpointing) |
| Codex CLI | Backtrack in the transcript with Esc and confirm a previous prompt with Enter. | The TUI restores the selected prompt to the composer and rolls the conversation back to before that turn. The explicit `/fork` command creates a fresh chat ID and preserves the original transcript. A local fork can use a new managed Git worktree. These commands document conversation and checkout choices without promising the historical dirty files of every repository. [Codex TUI implementation](https://github.com/openai/codex/blob/main/codex-rs/tui/src/app_backtrack.rs) · [Codex CLI commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli#fork-the-current-chat-with-fork) |
| Lazybox branch | Press Esc twice in an empty composer, choose a prompt with ↑ or ↓, then press Enter. Clicking **Restart from here…** on the prompt opens the same confirmation. | Review the prompt and choose the files before sending. The default in a managed workspace creates a child conversation and separate worktrees at the saved pre-prompt state. The original can continue. Choosing **Use current workspace files** shares today’s files and stops the previous continuation when restarting the prompt. [Workspace behavior](WORKSPACES.md) |

## How Lazybox reconstructs the starting point

1. **Capture the files locally.** Around each coding turn, the Runner records the ready repositories and writes each working tree through a temporary Git index. Private refs keep the snapshot commits reachable. This captures tracked edits and eligible untracked files, including changes made by a shell. Ignored files are excluded. Unchanged content can reuse a commit. The default retention is 100 turns per conversation. [Checkpoint implementation](services/runner/code/internal/runner/codecheckpoints/doc.go) · [Turn hooks](services/runner/code/internal/runner/code_checkpoints.go)
2. **Resolve the conversation separately.** The prompt’s timeline cursor identifies the operation. The Runner finds the previous completed native turn and excludes the selected prompt and subsequent messages. Codex forks through the last retained turn ID and checks the result. Claude’s worker records the final assistant message UUID for supported completed turns and forks its SDK session through that message. Restarting from the first eligible prompt needs no preceding provider history. [Boundary resolution](services/runner/code/internal/runner/conversation_fork.go) · [Codex adapter](services/runner/code/internal/runner/adapters/codex/codex.go) · [Claude worker](workers/claude-sdk/src/main.ts)
3. **Open the child, then send.** For an isolated restart, the Runner creates one worktree per recorded repository from its saved commit. An incomplete or unavailable checkpoint produces an error. The UI sends the revised prompt to the child and provides a link back to the source. Cancelling the initial review opens nothing. For a completed Codex reply, **Fork after this turn…** instead uses the history and files *after* the turn. [Runner fork](services/runner/code/internal/runner/conversation_fork.go) · [Confirmation and delivery](packages/surfaces/src/AgentWindow.tsx)

**Editing in place.** **Edit** on a prompt is the same-conversation counterpart of a restart, as in the providers' own CLIs: no child conversation and no new worktrees. The Runner resolves the same boundary, stops the agent, and starts the conversation's next attempt on a fork of the provider session that ends before the prompt. That attempt records the prompt's cursor as its cut, and the conversation's timeline reads the earlier attempts only up to it; the replaced records stay in their journals. Files are left as they are. After an edit the conversation has had more than one provider session, so a boundary is taken in whichever session recorded the turn, for a restart as for an edit. [Runner rewind](services/runner/code/internal/runner/conversation_rewind.go) · [Timeline](services/runner/code/internal/runner/timeline.go)

**Current limits.** The searchable picker shows message numbers and timestamps, explains disabled prompts and includes older messages as the transcript reader pages them in. The confirmation checks the provider boundary and names the repositories covered. Steered messages share the running turn’s file state, and prompts with attachments cannot currently be replayed. An older Claude turn recorded without the native UUID is found in Claude's transcript by the identifier of its last API message; one Claude has since compacted away cannot supply a bounded fork. A checkpoint captures repository contents during capture. It cannot recreate running processes, external services or ignored local configuration.

## Release roadmap

| Order | Deliverable | Acceptance check |
| --- | --- | --- |
| 1 · Validate the branch | Exercise installed Claude and Codex builds against the same two-repository workspace. Record the provider versions and run both file choices. | Put distinct uncommitted and untracked changes in both repos. Restart from the middle prompt. The isolated child sees both earlier file sets and only the earlier conversation. Its first edit leaves the source untouched. The shared-files choice displays its stop warning and uses the current contents. |
| 2 · Make availability visible | Have the Runner report whether each prompt has a usable native boundary and retained file snapshot. Show the workspace name, repository count and any reason a choice is unavailable before confirmation. | A pruned snapshot, skipped file, attachment, mid-turn message and legacy Claude boundary each produce a specific explanation. A failed historical restore never silently selects current files. |
| 3 · Cover long conversations and recovery | Page older eligible prompts into the picker. Exercise interrupted provisioning and delivery, including reopening the confirmation after a client reconnects. | A user can find an older retained prompt and distinguish two identical prompts. Retrying a lost response produces one child workspace and one delivered prompt. If delivery fails, the child and revised draft are recoverable. |
| 4 · Release and verify | Run the repository release gates and repeat the keyboard and mouse flows on a staged build before promotion. | Escape dismisses the picker without side effects. Keyboard focus returns to the composer. Returning from the child opens the intended source. Record the tested versions and the known exclusions in the release notes. |
