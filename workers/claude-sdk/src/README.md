# Claude SDK worker

`main.ts` hosts the pinned supported Agent SDK, streaming input, native permission/question callbacks, images, interruption, stopping one sub-agent (`stop_agent`), switching the model of the following turns (`model`, the SDK's `setModel`), and managed command tools. `browser.ts` gives coding agents the agent browser's thirteen `browser_*` tools on the `lazybox_browser` MCP server when the Runner offers it (`open` with `browser: true`), each routed to the Runner tool of the same name, screenshots returned as images, allowed without a per-call prompt because the Runner asks per site ([BROWSER.md](../../../BROWSER.md)). `catalog.ts` reports the agent's own slash commands and models once per change as `command_catalog` (from the initialize response, each turn's `init`, and `commands_changed`); a command is run by sending `/name args` as the message. `status.ts` reports a compaction as `compacted` and a local command's printed output as the agent's text. Sub-agent prose is forwarded (`forwardSubagentText`) and coding agents get progress summaries (`agentProgressSummaries`); `status.ts` attributes a sub-agent's text and tools by `parent_tool_use_id` and adds its brief, usage, summary and outcome to `agent_status` data. A run Claude forks without a task (a Skill with `context: fork`) is reported as a sub-agent from its first event to its call's result, and when the main turn ends anything it blocked on (a foreground task, a forked run) that never reported an end is reported `unknown` with reason `turn_ended`; background tasks are left running. `settings.ts` gives only the Help assistant the `lazybox_settings` MCP server: reading Lazybox's settings needs no approval, and an update runs only for an input the user allowed on its approval card. `permissions.ts` turns Claude's asks into approval cards with their "always allow" choices: one for the workspace is Claude's own rule in `.claude/settings.local.json`; one for the conversation is a grant the worker enforces and reports (`permission_grant`), which the Runner keeps with the conversation, opens every later worker with (`open` `grants`) and takes back on request (`revoke`). `steer.ts` hands a message to the running turn (`steer`, priority `next`): Claude Code folds it in between two steps, as its own terminal does; the worker refuses a steer while no turn runs, and the Runner keeps that message for its own turn. `interrupt.ts` applies an interrupt to the turn it was asked for and no other: one that failed, or arrived after its turn ended, leaves the next turn's failures as they are. When the SDK stream ends (`stream.ts`) the worker reports why (`provider_process_exit`, or `sdk_error`) and exits once that line is written, so the Runner sees the agent process end instead of a worker that accepts messages nothing reads. Go owns queueing, journals, account context, and command execution. Build with `make build-worker`; see `RUNNING.md` for limits.
