# React surfaces

`AgentWindow` is the public component: give it a resolved Runner connection and optionally an initial agent (Claude by default), working directory, or existing session ID. It owns authentication, discovery, session startup/attachment, event subscriptions, messages and generic file uploads (including native image input), request cards, interruption, and a command-output drawer. Drop files anywhere in an active chat to add them to the draft; dropping does not send. Every file is a box (`AttachmentBox.tsx`, `attachment-boxes.ts`); a large text paste becomes a pasted-text box. The picker, drops and pastes share Runner-advertised limits and the same byte-upload path; a file over a limit is an error box. Folders are rejected. `make test-attachments` checks embedded, detached, and standalone composers with fake RPC. Enter sends; Shift+Enter inserts a line; IME confirmation does not send. Unmounting disconnects readers without stopping execution. The host owns URL persistence and native window creation through optional callbacks. See [usage](../../../RUNNING.md#reusable-agent-window).

Work graph, previews, review, and native desktop surfaces remain future work.

Conversation navigation uses creation time with a stable ID tie-breaker. Choosing a row only changes the view; it does not refresh the Runner catalog or reorder conversations. A detached chat appears as a compact return control instead of reserving a blank pane. Older Runners expose live conversations, with an explicit notice that saved history requires a Runner update.

## Attention inbox

The header's **Inbox** (`] ] i`) brings the page's **Agents** panel (`AgentsPanel.tsx`, under Workspaces in every built-in layout) forward with its first row focused; only a page without one, or with it folded, gets the popover (`InboxDialog`), so the Inbox never reopens what the person closed. Closing or folding Agents is the window's choice (`workspace.sidebar-agents` preference, `fitSidebarAgents` in `workspace-model.ts`), applied to every page of every workspace on each load and commit; Panels → Agents, the palette's *Show Agents* and `⌃⌥⇧Esc` bring it back. Both list every work conversation of the Runner, across workspaces, grouped by what it needs: *Needs input* (a pending question or approval), *Failed* (a fault, a provider failure, a failed delivery, or a turn a Runner restart interrupted), *Ready for review* (a turn ended since you last looked), *Working*, and *Done*; newest first within a group. Each row shows the workspace, agent and model, age, and the agent's last line (`Session.last_message`) or the pending request. `j`/`k` move, Enter opens the conversation in its workspace, `m` marks it seen. The count on the entry is what needs you: needs input, plus unseen failures and finished turns. Sidebar rows carry the same unread marker. When the main turn ends with a sub-agent still running, the conversation stays under Working and keeps its spinning indicator until the background work finishes. Assistant panels ("Ask Lazybox") are not work items and are left out.

The state is a pure function (`attention.ts`, tested in `scripts/attention.test.ts`). *Seen* is local: a mark per conversation in localStorage under the Runner authority, shared live by every window of that Runner, so reading a conversation in a detached chat window clears it in the main window too. A conversation counts as seen while it is on screen in a focused window. The first look starts the record: turns that ended before it are not news.

Notifications come from the one window whose host can show them (the desktop main window; the main browser view): an entry into *Needs input* (each new request) or *Failed*, and optionally *Ready for review* (Settings → Notifications). Only a change that window watched, with new agent activity behind it, notifies — the first observation is a baseline, so a Runner restart that re-labels state without the agent doing anything never notifies — and never for the conversation you are looking at. While that window is in front the notice is an in-app toast (bottom right, with Open and the ⌘J hint) instead of a system banner; in the background it is a system notification. A burst becomes a summary. The dock badge counts conversations that need input. Clicking a notification or a toast opens its conversation. A short sound plays for *needs you* (input or a failure, on by default) and for *done* (a finished turn, off by default), switched, chosen and previewed in Settings → Notifications → Sounds (`sounds.ts`): Lazybox's chime (synthesized with Web Audio), a macOS system sound played by the desktop host (`configureSystemSounds`, `src-tauri/src/sounds.rs`), or a short file of the person's own (decoded and played through the same AudioContext); one volume; optionally only while Lazybox is in the background. Sound choices are this computer's, kept in browser storage. `npm run test:sounds` drives them. `npm run test:inbox` and `npm run test:command-palette` drive this against the fake Runner.

## New task and handing work over

`⌘N` (`task.new`, `NewTaskSheet.tsx`, pure model in `new-task-model.ts`) opens one sheet: the first message, the repositories (recent first, fuzzy search, chips; *Start without a repository*), the branch suggested from the message (editable with the workspace's name), the agent (the shared `AgentPicker`), the account when the provider has several, and the mode. Enter runs PrepareWorkspace, OpenSession and Apply in that order, each once (a retry resumes where it stopped, with the same request key and operation id); ⌘Enter does it in the background with a toast; Escape while starting moves it to the background, and before starting keeps the unsent message. The last repositories and mode are remembered (`new-task` preference). New task and New conversation share the last coding agent, account and model (`launch-choices` preference). The empty window and an empty Workspaces list offer it (`NewTaskStart`); `⌘⇧N` / `]] c` stay the quick New conversation in the workspace in front. `npm run test:new-task`.

A task can start from a GitHub issue (`WorkItems.tsx`, pure model in `item-context.ts`): a link pasted alone into the message box (resolved by `ResolveItemUrl`), **From an issue…** under it, or `task.fromIssue` (⌘K *Start from an issue…*) opens `ItemPicker` (`SearchItems`; ↑↓ Enter, Tab for the scope, Esc). `ItemSource` is the item's chip with exactly what the agent gets (`GetItem`'s `context`, or `contextWithoutComments` when the comments are unticked); the issue's repository is chosen, the name and branch come from it (`itemBranch`, the Runner's `workitems.Branch`), and the Runner default's YOLO becomes Ask (`itemSafeMode`). `StartedNotice` uses `FindItemWorkspaces` (Open it / Start another). The first message is the prompt, then the quoted context; `MessageList` shows that block as `QuotedItemChip` (`splitItemContext`), and the chat header shows `ItemOriginChip` for a workspace with an `origin`. `npm run test:start-from-issue`.

`handoff.tsx` (pure model in `handoff-model.ts`) adds **Open in Terminal** to conversation, Inbox, chat-header, workspace and Files menus and the palette (`terminal.external`), and **Continue in Claude Code / Codex…** (the provider's resume command with `cd`, copied) to conversation menus and the chat's ⋯. A desktop host opens the person's own terminal app (`configureExternalTerminal`; `src-tauri/src/terminal.rs` checks the window and asks the Runner that the folder is inside a workspace); a browser gets the `cd` to paste. The terminal choice (Settings → Agents & workspaces) is this computer's, kept in browser storage. `npm run test:chat-handoff`.

The Codex meter shows reported window usage. **Transcript size** groups observed text by tool outputs, assistant replies and user messages since the last observed compaction. Expand a group to inspect its five largest items. **Latest request details** shows the provider’s token types.

## Context menus

Inside the app a right-click opens a Lazybox menu for that place, never the browser's or macOS's; a long press on touch, Shift+F10 or the context-menu key on the focused element open the same menu. Arrows, Home/End, typing the start of a label, Enter and Escape work as in a native menu; a press outside, scrolling, leaving the window or Escape closes it, and one is open at a time. Text fields keep the native menu (spelling, paste, emoji); the Monaco editor keeps its own, in Lazybox colours; Alt+right-click shows the native menu in development, for Inspect Element.

A menu is assembled from sections, innermost first: Copy when the click is on a text selection, then each place under the pointer that declares a menu (a code block's items, then its message's). Where nothing declares one it offers Reload window. Wired: chat messages (quote in reply, copy, copy as Markdown, jump to prompt, the turn's checkpoint actions), agent turn markers, code blocks, web links, file references, Files rows, editor tabs, panel headers, the chat header (the ⋯ session actions), workspace and conversation rows (their ⋯ items, from the same list), Changes rows and diff lines (open, copy paths, add a review comment), processes, command output (stop, run again, copy the command or output), the terminal (copy, paste, select all, clear, send selection to agent) and Inbox rows. The desktop app adds Reveal in Finder and, in development, the inspector.

Features add items without editing the place that declares the menu: `registerContextMenu(scope, context => items)` or `useContextMenuContribution`. The scopes, the `detail` each receives and the item format are documented in the header of `ContextMenu.tsx`. The model (placement, keyboard, type-ahead) is pure and tested in `scripts/context-menu.test.ts`; `npm run test:context-menus` right-clicks every wired place in WebKit against the fake Runner.

## Dismissing dialogs and popovers

One rule everywhere (`dismiss.ts`): Escape closes the surface in front, and so does a click outside it. Over a modal dialog's backdrop the click is swallowed; beside a popover it goes on to what it landed on. Only a press and a release both on the backdrop count, so a text selection dragged out of a dialog never closes it. A dialog holding something the person typed or changed does not lose it to a stray click: it stays open and its footer (Cancel / Save) shakes, as a macOS sheet does; Escape, Cancel and × still close it. A busy dialog ignores the click as it ignores Escape, because the click asks through the same `cancel` event.

A context menu is the innermost surface while it is open: a press outside it, or Escape, closes the menu alone, never the dialog or popover under it (`claimPress`), and a press on the menu is the menu's. A dialog gives the focus back to what opened it when it closes, unless the close put it somewhere. A dialog of its own `<dialog>` names what a click outside would lose with `useBackdropDismiss`'s `holding` (the Inbox's "Ask for changes" note, whose Escape is Back).

`DraggableDialog` does all of this, so a new dialog gets it for free: a field changed since it opened (not a search field: `type="search"`, a combobox, or `data-dismiss-query`) guards it, and `draft="kept"` says the dialog keeps its draft when closed (New task), so it closes like Escape. A dialog of its own `<dialog>` uses `useBackdropDismiss`; a popover, picker or menu uses `useDismiss(open, close, [panel, trigger])`, which also gives the focus back where it was (the message box) when it would otherwise be lost. Native `popover="auto"` surfaces get light dismiss from the browser. `npm run test:dismiss-outside` drives it in WebKit.

Search dialogs keep their controls in place while a query filters or loads.
Give results a viewport-bounded height and their own scrollbar. Show loading,
empty and error states inside that region so the search field and footer stay
put. Verify the bounds with many, one and zero results at the same window size.

## Actions, keys and the command palette

Every command is declared once in `actions.ts` (id, title, group, icon, default keys, scope). Components register what an action does with `useAction`/`useActions` (or the older `useKeyboardAction`), optionally with a when-enabled predicate; `runAction(id)` runs it. The keymap (`keyboard.ts`), the `]]` which-key card, the command palette, the shortcuts overlay, the desktop menu bar (`nativeMenuItems`, published by the main window through the `set_action_menu` command and rebuilt when keys change) and context menus (`actionsFor`, `actionMenuItems`, which return items in `ContextMenu`'s shape) all read it.

Keys: a chord such as `Mod+k` (⌘ on a Mac, Ctrl elsewhere) fires from anywhere, text fields included, except chords the file editor owns (⌘K, ⌘/, ⌘[ …) while it has focus and Ctrl chords in a terminal. Sequences (`] ] i`) and bare keys (`?`) fire outside text fields, and a bare key typed in the message box stays text. A value may list alternatives with `or`. Keymaps saved before the registry (no `__version`), or before the latest actions with default keys (`keymapVersion`; 2 predates `] ] v` and `] ] b`), keep every saved key and gain the new actions' defaults in the saved leader, minus any key that would collide with a saved one or with an entry of the person's own `]]` menu (`migrateKeymap`).

The palette (⌘K or ⌘⇧P, `] ] p`) searches actions, conversations in every workspace, workspaces, files (Go to file's search), settings sections, panels, artifacts of every workspace (one in another workspace switches there and opens it) and missions; empty, it shows recent choices, what needs you, and all actions. `>` narrows to actions, `@` conversations, `#` workspaces, `/` files, `*` artifacts. In a detached chat window, going somewhere asks the main window (through localStorage, like attention) and brings it forward. The shortcuts overlay (`?`, ⌘/) lists every action with its keys, filterable, with Customize… to Settings → Shortcuts. Navigation: ⌘1…⌘9 the Nth workspace of the sidebar, ⌘J / ⌘⇧J the next / previous conversation that needs you across workspaces (needs input, unseen failures, unseen finished turns, in inbox order), ⌘] / ⌘[ the next / previous conversation of this workspace.

## Activity detail

Settings search matches section names and common terms. Search for “less verbose” or “command output” to jump to **Chat → Activity detail**, or open the existing Ask Lazybox panel from the results.

How much of an agent's tool activity a conversation shows (`tool-lines.ts`, rendered by `ToolLine.tsx`). **Quiet**, the default, keeps the agent's prose, decisions and edits, and folds a whole turn's calls into one line ("Worked for 2m 10s · 14 steps · 1 failed") on the turn's first run of calls, expandable; the step running now still shows. **Verbose** shows every call on its own line. Across all modes, command rows show nonzero exit codes and omit successful exit codes. Every mode keeps every call in the journal, the Activity dialog (searchable) and a line's details, and folding mounts fewer rows.

The session header shows the current activity mode. Click it to cycle modes. Each prompt also has a response detail selector. Choose Quiet, Verbose, or Hide response, then choose Session to follow the conversation again. Each prompt keeps its choice when you reopen or reload the conversation. Hover over a prompt for its acceptance time and the last model and context usage reported before acceptance.

The default is in Settings → Chat, with a live preview; a conversation can have its own from its ⋯ menu (and the header's context menu), the palette's "Activity detail: Quiet / Verbose / Use the default", or `] ] v` to cycle. Choosing the default again drops the conversation's own. Both are app preferences (`readPreference` under the Runner authority, `activity-detail.ts`), changed live in every chat of the window; a desktop window opened earlier reads a new default when it next opens. The palette and keys act on the chat last clicked or focused. `npm run test:activity-detail` drives all of it against the fake Runner.

## Colours, text sizes and themes

Stylesheets use design tokens only: `var(--surface)`, `var(--text-muted)`, `var(--danger-bg)`… for colours and `calc(12px * var(--text-scale))` (code: `--code-scale`) for text sizes, so themes, light mode and the text size settings reach everything. `scripts/appearance.test.ts` fails on a literal; `npm run tokenize-css -- file.css` converts one. Components that draw their own colours (Monaco, xterm, Mermaid, ANSI output, charts) take them from `appearance/`. See [Appearance](../../../APPEARANCE.md).

**Prompt history** in the composer searches this conversation's sent
prompts, including earlier prompts retained by the Runner. Each entry shows
its relative age and can switch to the exact time. Picking an entry puts it in
the composer for editing. Up and Down recall prompts from an empty composer,
and the transcript shows the send time on each prompt.

The **Recent** view in the Agents sidebar orders conversations by their
latest observed activity with timestamps and the latest status or message.
The **Priority** view groups conversations by what needs attention.

After a confirmed Codex handoff, returning to the source on the same device shows **Open continued Codex conversation** for that limit.

On a subscription limit card, **Show all subscriptions** opens the latest reported account states grouped by provider, including the current account and reported reset times.

On a tool approval card, **Allow and enable Full access** switches the conversation to Full access and accepts the pending request. The option appears for agents that support live permission changes, including for file edits. During planning, only the main Claude agent’s ExitPlanMode approval offers this choice. Accepting it switches the Runner workflow to execute as well. Subsequent ordinary main-agent command requests use a one-time approval automatically. Codex applies the new sandbox policy when the next turn starts.

Saved snippet text in drafts and sent prompts appears as a named chip. Hover, focus, or tap the chip to read the full text. **Edit prompt** opens the original draft, and **Collapse snippet text** restores the compact view. Matching uses the current snippet catalog; unmatched text stays visible.

After a successful pull request Inbox action, its button gives way to a delivery receipt and a ten-second auto-dismiss countdown. Dismiss closes it immediately. Failed actions remain available to retry.

Prompt Details shows the acceptance time, last provider-reported model and last reported context. Missing measurements are labeled unreported. An inserted review snippet retains its review action in the draft across reload. Pasting the same text creates an ordinary message. The Review tray records selected findings as sent when the Runner acknowledges the message.

For Codex replies with a turn boundary, **Ask a side question…** opens a separate conversation through that turn. The question goes to the child. The dialog identifies whether its files come from a checkpoint or the current workspace.

The Inbox sends a reaction for the displayed observation and destination. Updated Runners store the acknowledgement so another device or a retry can retrieve it. If the Runner stops between dispatch and saving its receipt, it reports the outcome as unknown and prevents an automatic second dispatch. Feedback requiring a person stays in the Inbox until dismissed. Dismissals from older clients without a Runner and observation identity may appear again.
